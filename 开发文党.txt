**版本**：v1.0.0-draft

**参考项目**：AIPentest/CyberStrikeAI


## 1. 项目概述

### 1.1 项目定位

dsh-cyber 是一个基于 DSH Desktop 二次开发的 **AI 原生安全智能执行中枢桌面版**。它将 CyberStrikeAI 的安全能力（AI 智能体编排、YAML 工具配方、资产/漏洞管理、攻击链建模）以 **Cordis 插件**的形式集成到 DSH Desktop 的 Electron 壳中，产出 Windows 可安装的 `.exe` 和便携版 `.exe`。

### 1.2 核心设计原则

**不 Fork 上游源码**：DSH Desktop 的设计哲学是“桌面本身也是插件”，一切通过 Cordis 插件的 `apply` 函数、`inject` 声明、`ctx.effect()` 生命周期来扩展。dsh-cyber 必须以独立插件形式存在，不修改 `dsh-plugin-desktop` 源码。

**跨语言桥接**：CyberStrikeAI 是 Go 语言构建的单体 Web 应用，使用 Eino 框架做多智能体编排。dsh-cyber 用 **TypeScript 重新实现**其核心逻辑，工具通过 Node 子进程调用，不移植 Go 代码。

**高风险功能默认关闭**：WebShell 管理和 C2 功能在第一期只做 UI 占位符和审批流接口，不实现可用的执行器。

**许可证合规**：CyberStrikeAI 使用 **AGPL-3.0 许可证**（另有来源显示为 Apache 2.0，需以实际仓库为准）。dsh-cyber 不得直接复制 CyberStrikeAI 的源码，只参考功能设计，独立实现。

### 1.3 技术栈对比

| 维度 | DSH Desktop（基础） | CyberStrikeAI（参考） | dsh-cyber（目标） |
|---|---|---|---|
| 运行时 | Electron + Node.js | Go 1.24+ | Electron + Node.js |
| 插件系统 | Cordis（一切皆插件） | MCP + Eino | Cordis 插件 |
| 前端 | Web UI（Slot 机制） | 静态前端 | Web UI（复用 Slot） |
| 持久化 | DSH storage / 插件自有 | SQLite | better-sqlite3 |
| AI 编排 | DSH Agent 运行时 | Eino（Deep/Plan-Execute/Supervisor） | DSH Agent + 自建编排层 |
| 工具集成 | 插件路由/RPC | MCP + YAML 配方 | YAML 配方 + Node 子进程 |
| 打包 | electron-builder | Go 编译 | electron-builder |


## 2. 架构设计

### 2.1 整体架构

DSH Desktop 的 Electron 可执行文件只包含最小启动代码，它获取单实例锁、解析选中的 DSH profile、提供原生运行时能力，并在 Electron main 进程中启动 **Host Cordis 根**。`desktop-shell` Host 插件通过 Cordis effect 拥有 `BrowserWindow`、导航策略、settings namespace 和关闭/退出生命周期。

dsh-cyber 作为新增的 Cordis 插件，同时提供 **Host service** 和 **Web Client** 两个 face。Host face 运行在 Electron main 进程的 Host Cordis generation 中，Client face 渲染在沙箱化的 renderer 中。

### 2.3 Cordis 插件机制要点

**插件声明**：每个 Cordis 插件通过导出 `apply(ctx)` 函数来注册能力。Desktop 专用插件通过 `inject` 声明对 `desktopProfiles` 和 `desktopPnpm` 的依赖。

**effect 生命周期**：插件通过 `ctx.effect(() => { return async () => { /* 清理逻辑 */ } }, '描述')` 注册副作用，确保插件卸载时副作用可完整回滚。

**兼容模式**：如果插件需要同时在普通 `dsh web` 和 Desktop 中运行，不要将 Desktop service 放在顶层 `inject` 中，而是先注入普通依赖，再通过 `ctx.get('desktopProfiles')` 动态探测。


## 3. 插件开发规范

### 3.1 插件入口（Host face）

```typescript
// dsh-plugin-cyber/src/host/index.ts
import type { Context } from '@deepseek-ai/cordis'
import { CyberDatabase } from './database'
import { AuditLogger } from './audit'
import { ToolRegistry } from './tools/registry'
import { AgentOrchestrator } from './agent/orchestrator'

export const name = 'dsh-plugin-cyber'
export const inject = ['webServer', 'loader']

export function apply(ctx: Context, config: CyberConfig): void {
  // 1. 初始化数据库
  const db = new CyberDatabase(ctx, config.dbPath)

  // 2. 初始化审计日志
  const audit = new AuditLogger(db)

  // 3. 注册工具配方
  const tools = new ToolRegistry(ctx)
  tools.loadRecipes('recipes/')

  // 4. 初始化 AI 编排器
  const orchestrator = new AgentOrchestrator(ctx, { db, audit, tools })

  // 5. 注册 HTTP 路由
  ctx.route('/api/cyber/assets', assetHandler(db))
  ctx.route('/api/cyber/vulnerabilities', vulnHandler(db))
  ctx.route('/api/cyber/audit', auditHandler(audit))
  ctx.route('/api/cyber/agent/stream', agentStreamHandler(orchestrator))

  // 6. 注册 Cordis service
  ctx.service('cyberDB', db)
  ctx.service('cyberAudit', audit)

  // 7. 注册 effect 清理
  ctx.effect(() => {
    return async () => {
      await orchestrator.dispose()
      db.close()
    }
  }, 'dsh-cyber cleanup')
}
```

## 4. 核心功能模块

### 4.1 AI 智能体编排

CyberStrikeAI 使用 Eino 框架支持单智能体及 Deep、Plan-Execute、Supervisor 多智能体模式。dsh-cyber 在 TypeScript 中重新实现：

```typescript
// dsh-plugin-cyber/src/host/agent/orchestrator.ts
export class AgentOrchestrator {
  async run(mode: AgentMode, input: AgentInput): Promise<AgentOutput> {
    switch (mode) {
      case 'single':
        return this.runSingleAgent(input)
      case 'plan-execute':
        return this.runPlanExecute(input)
      case 'deep':
        return this.runDeepAgent(input)
      case 'supervisor':
        return this.runSupervisor(input)
    }
  }

  private async runPlanExecute(input: AgentInput): Promise<AgentOutput> {
    // 1. Planner Agent 生成执行计划
    const plan = await this.plannerAgent.plan(input.message)
    // 2. 逐步骤执行
    const results = []
    for (const step of plan.steps) {
      const result = await this.executorAgent.execute(step)
      results.push(result)
      if (result.requiresApproval) {
        await this.approvalWorkflow.requestApproval(result)
      }
    }
    // 3. 汇总结果
    return this.summarize(results)
  }
}
```

```typescript
// dsh-plugin-cyber/src/host/tools/recipe-parser.ts
export interface ToolRecipe {
  name: string
  display_name: string
  category: string
  command: string
  args: ToolArg[]
  timeout: number
  risk_level: 'low' | 'medium' | 'high' | 'critical'
  requires_approval: boolean
  output_parser?: string
}

export class RecipeParser {
  parse(filePath: string): ToolRecipe {
    const content = fs.readFileSync(filePath, 'utf-8')
    const raw = yaml.parse(content)
    return this.validate(raw)
  }
}

// dsh-plugin-cyber/src/host/tools/executor.ts
export class ToolExecutor {
  async execute(recipe: ToolRecipe, params: Record<string, any>): Promise<ToolResult> {
    const args = recipe.args.map(a => params[a.name] ?? a.default)
    const startTime = Date.now()

    const { stdout, stderr, exitCode } = await execFileAsync(
      recipe.command,
      args,
      { timeout: recipe.timeout * 1000 }
    )

    const result: ToolResult = {
      recipe: recipe.name,
      params,
      stdout,
      stderr,
      exitCode,
      duration: Date.now() - startTime,
      timestamp: new Date().toISOString()
    }

    // 审计记录
    await this.audit.append({
      action: 'tool_exec',
      recipe: recipe.name,
      params,
      result: { exitCode, duration: result.duration }
    })

    return result
  }
}
```

### 4.3 审计哈希链

采用 SQLite 哈希链 + 只追加 JSONL 方案。每条审计日志的哈希值包含上一条日志的哈希值，形成链式结构。一旦任何记录被篡改，后续所有哈希值将不匹配。

```sql
-- dsh-plugin-cyber/src/host/database/schema.ts (SQL 部分)
CREATE TABLE IF NOT EXISTS audit_log (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  seq         INTEGER NOT NULL,
  timestamp   TEXT    NOT NULL,
  action      TEXT    NOT NULL,
  actor       TEXT,
  target      TEXT,
  detail      TEXT,      -- JSON
  prev_hash   TEXT,
  hash        TEXT    NOT NULL,
  chain_key   TEXT    NOT NULL DEFAULT '@system',
  UNIQUE(chain_key, seq)
);

CREATE INDEX idx_audit_chain ON audit_log(chain_key, seq);
```

```typescript
// dsh-plugin-cyber/src/host/audit/hash-chain.ts
import { createHash } from 'node:crypto'

export class AuditLogger {
  private db: CyberDatabase
  private jsonlPath: string

  async append(entry: AuditEntry): Promise<void> {
    const prev = this.getLastEntry(entry.chainKey ?? '@system')
    const seq = (prev?.seq ?? 0) + 1
    const prevHash = prev?.hash ?? null

    const payload = {
      seq,
      timestamp: new Date().toISOString(),
      action: entry.action,
      actor: entry.actor ?? '@system',
      target: entry.target,
      detail: JSON.stringify(entry.detail),
      prev_hash: prevHash
    }

    const hash = createHash('sha256')
      .update(JSON.stringify(payload))
      .digest('hex')

    // 写入 SQLite
    this.db.prepare(`
      INSERT INTO audit_log (seq, timestamp, action, actor, target, detail, prev_hash, hash, chain_key)
      VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)
    `).run(seq, payload.timestamp, payload.action, payload.actor,
           payload.target, payload.detail, prevHash, hash, entry.chainKey ?? '@system')

    // 追加写入 JSONL
    fs.appendFileSync(this.jsonlPath, JSON.stringify({ ...payload, hash }) + '\n')
  }

  async verify(chainKey = '@system'): Promise<VerifyResult> {
    const rows = this.db.prepare(
      'SELECT * FROM audit_log WHERE chain_key = ? ORDER BY seq ASC'
    ).all(chainKey)

    let brokenAt: number | null = null
    let expectedPrevHash: string | null = null

    for (const row of rows) {
      // 检查 prev_hash 链
      if (row.prev_hash !== expectedPrevHash) {
        brokenAt = row.seq
        break
      }
      // 重算 hash 验证
      const payload = {
        seq: row.seq,
        timestamp: row.timestamp,
        action: row.action,
        actor: row.actor,
        target: row.target,
        detail: row.detail,
        prev_hash: row.prev_hash
      }
      const computed = createHash('sha256')
        .update(JSON.stringify(payload))
        .digest('hex')

      if (computed !== row.hash) {
        brokenAt = row.seq
        break
      }
      expectedPrevHash = row.hash
    }

    return {
      ok: brokenAt === null,
      total: rows.length,
      brokenAt
    }
  }
}
```

### 4.5 审批中心与治理

```typescript
// dsh-plugin-cyber/src/host/approval/workflow.ts
export type RiskLevel = 'low' | 'medium' | 'high' | 'critical'

export interface ApprovalRule {
  riskLevel: RiskLevel
  requiresApproval: boolean
  approver: 'user' | 'audit-agent' | 'both'
}

export class ApprovalWorkflow {
  private rules: ApprovalRule[] = [
    { riskLevel: 'low',      requiresApproval: false, approver: 'user' },
    { riskLevel: 'medium',   requiresApproval: true,  approver: 'user' },
    { riskLevel: 'high',     requiresApproval: true,  approver: 'both' },
    { riskLevel: 'critical', requiresApproval: true,  approver: 'both' },
  ]

  async check(recipe: ToolRecipe, params: Record<string, any>): Promise<ApprovalResult> {
    // 1. 检查工具白名单
    if (!this.isWhitelisted(recipe.name)) {
      return { approved: false, reason: '工具不在白名单中' }
    }

    // 2. 检查风险等级
    const rule = this.rules.find(r => r.riskLevel === recipe.risk_level)
    if (rule?.requiresApproval) {
      return this.requestApproval(recipe, params, rule)
    }

    // 3. 审计记录
    await this.audit.append({
      action: 'approval_auto_pass',
      recipe: recipe.name,
      params
    })

    return { approved: true, reason: '自动放行（低风险）' }
  }
}
```

### 5.5 更新策略

测试阶段使用 **GitHub Releases 作为 generic URL** 更新源，不开启静默自动更新。在设置页提供“手动检查更新”按钮：

```typescript
async function checkForUpdates(): Promise<void> {
  const res = await fetch(
    'https://api.github.com/repos/liumiya63-arch/dsh-cy/releases/latest'
  )
  const release = await res.json()
  const latestVersion = release.tag_name.replace(/^v/, '')
  const currentVersion = app.getVersion()

  if (semver.gt(latestVersion, currentVersion)) {
    showUpdateDialog({
      version: latestVersion,
      url: release.assets.find(a => a.name.includes('Portable'))?.browser_download_url
    })
  } else {
    showNotification('当前已是最新版本')
  }
}
```

### 8.3 常见问题

**Q：为什么不能在 renderer 中直接访问文件系统？**  
A：DSH Desktop 的 renderer 是沙箱化的，不暴露原始 Electron API。所有文件操作必须通过 IPC 或 HTTP 路由在 Host 端执行。

**Q：如何调试插件？**  
A：在 Host 端使用 `ctx.logger.info()` 输出日志，在 Client 端使用浏览器 DevTools（DSH Desktop 支持开发者模式）。

**Q：工具执行超时怎么处理？**  
A：`ToolExecutor.execute()` 中通过 `execFileAsync` 的 `timeout` 选项控制，超时后自动 kill 子进程并记录审计日志。
